# MacMon — macOS 资源监控 + 卡顿预警

菜单栏常驻，监控 **CPU / 内存 / Swap / 网络 / 每个应用的网络连接 / 磁盘读写 / 所有磁盘容量 / 发热**，异常时发系统通知，可一键结束卡死的应用。
纯 Swift + SwiftUI + 系统内核 API，无第三方依赖。

## 安装

```bash
./build.sh install   # 编译并安装到 /Applications，自动重启
```

首次打开会请求通知权限。建议在「⋯ → 守护模式」打开：开机自启 + 崩溃/卡死自动重启。

## 界面

- **菜单栏**：图标 + `CPU%  内存%`，正常时单色，告警时变橙/红
- **点击图标 → 弹窗**：健康状态、CPU / 内存 / 网络 / 磁盘读写四张卡片（含 3 分钟曲线）、所有磁盘容量、占用最高的应用（按 CPU / 内存 / 磁盘 / 连接排序；悬停出现 🌐 查看网络连接、⊗ 结束整个应用）
- **监控窗口**（弹窗右下角 🗔）：每核占用、内存构成（App / 联动 / 压缩 / 缓存）、应用 / 进程完整列表
- **网络连接明细**（应用旁的 🌐）：它正在连哪些远端（自动反查域名、标注 HTTPS/DNS/APNs 等端口）、开了哪些监听端口（标出「局域网可访问」的）。打开期间每 3 秒刷新
- **设置**（⚙︎）：所有报警阈值、提示音、守护模式

> Electron / Chrome 这类应用会拆成几十个 Helper 进程，MacMon 会把它们**合并到主应用名下**统计（×N 表示进程数）。

## 报警规则

| 报警 | 触发条件（默认，可在设置里改） |
|---|---|
| 🥵 CPU 持续高占用 | 整机 CPU > 85% 持续 30 秒 |
| 🔥 应用持续吃 CPU | 某应用全部进程合计 > 100%（1 个核）持续 60 秒 |
| 🔥 进程占用过高 | 单进程 > 60% 持续 3 分钟 |
| 😰 内存吃紧 | 已用 > 92% 且系统有内存压力，或可用 < 200MB |
| 🚨 系统内存压力 | macOS 内核发出 warning / critical |
| 🚨 Swap 暴涨 | 3 秒内 swap 增长 > 512MB |
| 🐘 应用内存过大 | 某应用合计 > 物理内存 30% |
| 🌐 网络连接异常多 | 某应用合计 > 500 个连接（狂发请求 / 连接泄漏） |
| 💾 磁盘空间不足 | 系统盘剩余 < 10GB |

同类报警默认 10 分钟内只提醒一次。

## Webhook 推送

「设置 → 通知」可添加多个 Webhook，报警、自动结束应用、MacMon 自我恢复会同时推送（带电脑名称）：

| 类型 | 说明 |
|---|---|
| 企业微信群机器人 | 群聊 → 群机器人 → 添加 → 复制 Webhook 地址 |
| 钉钉群机器人 | 支持「加签」密钥；或安全设置选关键词 `MacMon` |
| 飞书群机器人 | 支持签名校验密钥 |
| Slack | Incoming Webhooks |
| 自定义 JSON | POST `{source, host, title, body, category, time}`，可接自己的服务 / n8n 等 |

每个 Webhook 都有「发送测试消息」按钮，并按各平台返回码（errcode / code）判断是否真正成功。请求在后台发送、8 秒超时、在途上限 8 个，网络不通时直接放弃，不会影响 MacMon。

## 自动处理（默认关闭）

在「设置 → 自动处理」开启，并把允许自动结束的应用加入名单。**以下条件全部满足才会动手**：

| 安全阀 | 说明 |
|---|---|
| 名单 | 只处理名单里的应用；名单外的永远只报警。Finder、Dock、WindowServer、MacMon 自己等加了也不会处理 |
| 系统真的卡 | CPU 路线：整机 CPU ≥ 80% **且** 该应用合计 ≥ 200%（2 核）持续 3 分钟；内存路线：内存压力「严重」（或「警告」且 Swap ≥ 75%）**且** 该应用 ≥ 3GB 持续 30 秒 |
| 动手那一刻仍满足 | 条件必须在决定时依然成立，旧的计时不会触发 |
| 不碰前台应用 | 你正在使用的应用永远不会被自动结束 |
| 先礼后兵 | 先请求正常退出（等同 ⌘Q，应用可保存），5 秒后仍未退出才强制结束 |
| 限速 | 10 分钟内最多自动结束 1 个 |
| 事后告知 | 发通知说明结束了谁、为什么、占用多少，并写入日志 |
CPU 报警里出现「主要耗在内核」说明是内存不足导致疯狂换页，应关**内存**大户。

## 低开销设计

实测（M2 / 8GB）：**后台 0.22% CPU、约 15–30MB 内存；单轮采样约 2–7ms**。弹窗打开时约 2%。

| 数据 | 取法 | 为什么便宜 / 不会卡 |
|---|---|---|
| CPU（含每核） | `host_processor_info` | 1 次 Mach 调用 |
| 内存 / 压力 / Swap | `host_statistics64` + `sysctl` | 口径同「活动监视器」 |
| 进程 CPU / 内存 / 磁盘 IO | `proc_pid_rusage` | **每进程 1 次系统调用**拿全三项；进程名缓存 |
| 网络 | `sysctl(NET_RT_IFLIST2)` | 1 次调用取全部网卡 64 位计数器 |
| 每应用网络连接 | `proc_pidinfo(LISTFDS)` + `proc_pidfdinfo(SOCKETINFO)` | 只读内核套接字表，300 个进程约 0.6ms；明细只在打开时读 |
| 域名反查 | `getnameinfo`，后台并发 ≤4、名额满就跳过、结果缓存 | DNS 卡住也不影响界面和采样 |
| 磁盘读写 | IOKit `IOBlockStorageDriver` 统计 | 读注册表，设备列表 30 秒刷新一次 |
| 磁盘容量 | `getfsstat(MNT_NOWAIT)` | 只读缓存，**网络盘掉线也不会卡**；15 秒刷新一次 |
| 界面 | SwiftUI | **只在弹窗/窗口可见时刷新**；关闭后菜单栏文字没变化也不重绘 |

不调用任何外部命令（ps / top / nettop / iostat）。

## 自身防卡死

| 机制 | 说明 |
|---|---|
| 采样与 UI 分离 | 采样在后台串行队列，主线程只刷界面 |
| 看门狗线程 | 主线程 >20s 无心跳、采样 >90s 未完成、自身内存 >300MB → 立即自我重启，并通知原因 |
| 防误判 | 看门狗自己被饿死时（整机卡）只重置计时；系统睡眠不计时 |
| 守护模式 | launchd KeepAlive：崩溃 / 被杀 / 看门狗重启后 1 秒内拉起；菜单「退出」则不拉起 |
| 外部命令超时 | 仅 launchctl，5–10s 超时强杀，且不在主线程 |
| 图标异步加载 | 应用图标在后台线程读取并缓存 |
| 异步日志 | 磁盘卡住不影响采样 |
| 关闭 App Nap | 后台不会被系统节流 |
| 单实例 | 重复打开只会弹出已运行实例的弹窗 |

自检看门狗（需先关闭守护模式）：`MACMON_SELFTEST_HANG=3 ./MacMon.app/Contents/MacOS/MacMon`，3 秒后故意卡死主线程，约 20 秒后自动重启。

## 已知限制

- 普通权限读不到 root 进程（kernel_task、WindowServer 等）的明细，它们的消耗体现在 CPU「系统」占比里
- 没有公开 API 可以按进程统计网络**流量**（能看每个应用的连接，流量只有总数）
- 代理开了 TUN / fake-ip 模式时，远端都是 198.18.x.x 虚拟地址，真实域名只有代理软件知道
- macOS 没有公开 API 判断应用「未响应（彩虹球）」，靠 CPU / 内存 / Swap 间接判断

## CLI

```bash
./macmon status          # 系统快照 + 诊断
./macmon top             # 谁在吃 CPU（--by mem 按内存）
./macmon run             # 前台持续监控（与 App 二选一）
```

```
Sources/Sampling.swift   # 采样层（App/CLI 共用）
Sources/Engine.swift     # 报警引擎

app/AutoKill.swift       # 自动处理（决策 + 执行）
app/AppIcon.icns         # 应用图标（tools/icon 生成）
macmon.swift, main.swift # CLI
~/.macmon/macmon.log     # 报警日志
```
